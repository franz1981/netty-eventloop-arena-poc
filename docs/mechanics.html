Arena Mechanics

One space of the per-event-loop arena, blocks drawn with 16 slots. Step through allocations, releases and end-of-iteration hooks and watch the bump, the counters, the mask and the pinned state. This is the DEFAULT behaviour, -Darena.ring=false: a block is reused only at a hook. With -Darena.ring=true the tail also wraps inside a block below the oldest live start, and a stalled ring re-enters another block — not animated here.

live buffer released, behind the bump: not reusable until a hook never used bump pointer
  1. The bump only advances. A release only increments frees.
  2. A block is reset only at a hook, and only when allocs == frees. The current block resets in place; any other empty block gets its bit in reusableMask.
  3. A block with a live buffer at the hook is pinned: not reset, its released bytes stay unavailable. If it is the current block, its free tail is still bumped.
  4. When the current block is full: take the lowest set bit of the mask, else grow (up to 8 blocks), else delegate to adaptive until the next hook.
  5. Requests above the cap (8 KiB, a block is 256 KiB) never enter; a request never spans two blocks.
